## 1. WinPlax (референс) — `params.json → build_window_model → export_to_dxf`

DXF: `output/OK1_WINPLAX_OUTSIDE.dxf` (72K) / `OK1_WINPLAX_INSIDE.dxf` (89K)

```
cell_w = (1440 -2*60 -(3-1)*80)/3 = 386.666
cell_h = (1440 -2*60 -(2-1)*80)/2 = 605.0  (с подставочником 30 сдвиг низа)
frame_outer (30,60)-(1470,1470), frame_inner (90,120)-(1410,1410), mitres 45°
mullions_v: 2 шт. цельные (vertical) [(476.6,120)-(556.6,1410)], [(943.3,120)-(1023.3,1410)]
mullions_h: 3 шт. порезанные [(90,725)-(476.6,805)] ...  (горизонталь режется вертикальными, разрыв =80)
fillings: 272.7×491 и т.д.  falz 5  (штапик 20 → заполнение +5 внутрь от cell/inner_rect)
bead OUTSIDE 0 (скрыт), INSIDE 24 шт. per-cell outer larger (x1-bw ... x2+bw)
```

Соответствует ТЗ v0.2+п.21-27 и дополнению 2026-09-23 (каждая ячейка обрамлена штапиком, глухие корректно, створка острая к острой, per-cell 45° continuous auto).

## 2. `MadScrewdriver/qsketchmetric` — 2D parametric DXF через QCAD xdata

DXF: `OK1_qsketchmetric_PARAMETRIC.dxf` (19K) → `OK1_qsketchmetric_1500x1500_ABSTRACT60-80.dxf` (18K) и др.

**Как устроен:**
- Входной DXF: `LINE`/`CIRCLE`/`ARC` с `XDATA QCAD c:<выражение>` + `MTEXT "----- custom -----"` со списком переменных `W:1500 / FW:60 / MW:80`
- `Renderer(input_param.dxf, output_dxf, variables={W:1500,...}).render()` — DFS по графу, растягивает длины, сохраняет углы
- `layers: Frame/Mullion/VIRTUAL_LAYER`, `LWPOLYLINE` не поддерживается

**Попытка ОК-1:**
- Создан параметрический шаблон: внешний прямоугольник `W×H`, внутренний `W-2*FW × H-2*FW`, митры `FW*1.414`, 2 вертикали +1 горизонталь, виртуальные связи
- Рендер для `1500×1500`, `900×900`, `S571 58/77`, `REHAU 63/76` — bbox остаётся `1500×1545` (ошибка: меняет только длины, не положения импостов)

**Вывод:**
- `−` не умеет `LWPOLYLINE` с шириной (рама как полилиния), `−` не умеет `continuous auto` (вертикаль цельная / горизонталь резанная с разрывом), `−` не знает `bead outer larger 20` / `sash 80+20` / `filling -5` / `блоки/атрибуты/размеры`
- `+` идея хранения выражений в DXF (`c:W-2*FW`) полезна для WinPlax — можно вынести в MTEXT шаблона

**Код:** `ok1_qsketchmetric.py` (репозиторий `MadScrewdriver/qsketchmetric`, `MIT`, `pip install qsketchmetric`)

## 3. `IfcOpenShell / api.geometry.add_window_representation` — IFC BIM 779 строк

DXF-mock: `OK1_IFC_mock.dxf` (21K), `.ifc` не сгенерирован (модуль не установлен в sandbox)

**Как устроен:**
- `IfcWindow { OverallWidth:1440, OverallHeight:1440, PartitioningType }`
- `createIfcWindowFrameSimple([LEFT,TOP,RIGHT,BOTTOM])` с `LShapeCheck` (45° митра рамы)
- `partitioning types: SINGLE_PANEL, DOUBLE_VERTICAL/HORIZONTAL, TRIPLE_VERTICAL/HORIZONTAL/...` (9 пресетов)
- `frame_thickness 60, frame_depth 70, mullion 80, transom 80, lining`
- `Pset_WindowCommon` (IsExternal, GlazingAreaFraction, ThermalTransmittance...)

**Попытка ОК-1 3×2:**
- Формула IFC совпадает с WinPlax: `cell_w = (Overall -2*frame -(cols-1)*mullion)/cols = 386.666` — совпало 1:1
- Но `PartitioningType` ограничен 9 пресетами, нет `3×2` → нужно `SINGLE_PANEL + ручные IfcMember mullions/transoms` (как WinPlax делает `mullions_v/h`)
- IFC не знает `bead 20 outer larger`, `sash overlap 8+20=28`, `continuous auto`, `falz 5`, `dimensions/blocks`

**Вывод:**
- `+` математика деления и `LShape` — эталон для проверки WinPlax (замыкание `1e-6`)
- `+` полезны `Pset_WindowCommon` для паспорта изделия (тепло/звуко)
- `−` для 2D DXF фасада WinPlax богаче (штапик per-cell, створки двухконтурные)

**Код:** `ok1_ifc_openshell.py`, репозиторий `IfcOpenShell/IfcOpenShell` PR #118 `add_window_representation`

## 4. `OpenAEC/open-pdf-studio` + `Srusht22/ProFrame` — frame element (самый близкий)

DXF: `OK1_FrameElement_OpenPDFStudio.dxf` (32K), `OK1_FrameElement_S571_58-77.dxf` (19K)

**Как устроен:**
- `open-pdf-studio`: `frame element` вдоль линии стены: `length 1440`, `preset = curtain wall (алюминий) / window frame 67×114 с фальцем`
  - `outer frame` + `mullions` на границах полей + `panel` (glass double line 42, solid штриховка, door 40mm)
  - Операции: `add/remove/move/swap mullion`, `setPanel`, `divide`, `stretch`; `indeling.js / weergave.js / kozijnprofiel.js` (профили 67×114, bead 20)
  - План `1:1`: mullion `filled rect`, glass `double line`, поворот `dashed arc`
- `ProFrame`: `OpeningModel(DesignRegions) → RegionSolver → mm geometry → 2D elevation / 3D Three.js / price`
  - `frame face/depth, sash face/depth, mullion face, bead, infill 24/32/40/42`

**Попытка ОК-1:**
- Использована та же модель `build_window_model` (strips_x/strips_y), но отрисовка в стиле `frame element`:
  - `outer frame` + `mullions_v 2 цельные, mullions_h 3 порезанные` (как `continuous vertical`)
  - `panels`: 6 полей `glass double line` (`filling 272.7×491` как `falz 5`)
  - `bead`: `INSIDE` 24 полосы outer larger (скопированы из WinPlax)
  - `sash`: `inner_rect` + митры 45° + индикаторы `TURN/TILT`

**Вывод:**
- `+` декомпозиция 1:1 с WinPlax: `outer + mullions (filled rect) + panels (glass)` — лучший донор
- `+` `continuous` логика совпадает, но в `open-pdf-studio` выбор ручной (Vertical/Horizontal), в WinPlax — `auto по наименьшей стороне + радиокнопка мастера`
- `−` bead в `open-pdf-studio` — часть `kozijnprofiel.js` (один выступ), в WinPlax — `4 полосы per-cell outer larger` с митрой `острая к острой` и обрезкой створкой
- `−` sash в `open-pdf-studio` — `door 40мм + arc`, в WinPlax — `80+20 двухконтурная, overlap 8+20=28, Inner/Outer`

**Рекомендация:** взять у них `panel catalogue` и `indeling.js` (каталог заполнений `24/32/40/42`) для `profiles.json`

**Код:** `ok1_frame_element.py`, репозитории `OpenAEC-Foundation/open-pdf-studio` PR #484/#485, `Srusht22/ProFrame`

## 5. `CadQuery / build123d / FreeCAD-WindowFrames` — 3D B-Rep (OCCT)

DXF-mock: `OK1_CadQuery_FreeCAD_mock.dxf` (22K), `STEP` не собран (CadQuery не установлен в sandbox, требуется `OCP`)

**Как устроен:**
- `CadQuery`: `Workplane("XY").box(1440,1440,70).cut(box(1320,1320,70).translate(60,60)).union(mullions)` → `STEP/STL`
  - Профили экструдируются вдоль периметра: рама `60×70`, импост `80×70`, штапик `20×15`
- `build123d`: `pythonic` обёртка OCCT, `FreeCAD`: `geometry.py` box layout + `scaling.py` RR `1:22.5..1:220` + `stl_writer.py`
- `FreeCAD-WindowFrames`: `Rough opening W×H`, `panes rows×cols`, `Fixed/DoubleHung` (`LowerSashOpen 0-100%`), `geometry.py` tests

**Попытка ОК-1:**
- `FreeCAD WindowFrames geometry.py` → `box layout` полностью совпадает с `WinPlax strips_x/strips_y`: `FRAME_W + i*(cell_w+MULLION_W)`
- `CadQuery` мог бы собрать тот же проём в `3D` (экструзия 70) и отдать заводу `STEP` (попробовано в коде, но требует `pip install cadquery`)

**Вывод:**
- `+` валидатор геометрии (проверить замыкание `grid` vs `cell` vs `mullion`)
- `+` из `build_window_model` можно сделать `STEP/STL` одной функцией `extrude(frame/mullions, depth=70)` — полезно для ЧПУ/заводов
- `−` не знают ТЗ WinPlax: `bead per-cell`, `sash overlap`, `falz`, `ГОСТ размеры`, `блоки/атрибуты/R2013 cp1251`

**Код:** `ok1_cadquery_freecad.py`, репозитории `CadQuery/cadquery`, `gumyr/build123d`, `FreeCAD/FreeCAD`, `jsinger0420/FreeCAD-WindowFrames`
