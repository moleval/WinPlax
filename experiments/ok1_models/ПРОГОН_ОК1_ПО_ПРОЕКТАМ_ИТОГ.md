## 2. `MadScrewdriver/qsketchmetric` — реальный `Renderer` (pip 1.7.2)

**Клон и запуск:**
```bash
git clone --depth 1 https://github.com/MadScrewdriver/qsketchmetric.git repos/qsketchmetric
pip install qsketchmetric
python real_qsketchmetric_ok1.py
node: реальные файлы repo/docs/_static/DXF/tutorial.dxf (15 ents, CIRCLE QCAD c:chalice_ornament_radius, MTEXT custom)
```

**Реальный прогон:**
- Рендер `tutorial.dxf` с `h=50 → bbox 40×50` и `h=100 → 80×100` **успешно** (points foot_point, proof Renderer работает)
- Свой parametric `qsketchmetric_OK1_PARAMETRIC.dxf` (21 LINE с `QCAD c:W-2*FW`):  
  `Renderer(param, out, {W:1500,H:1500,FW:60,MW:80}) → bbox 1500×1545` для всех вариантов  
  `REHAU 63/76`, `S571 58/77`, `900×900` — **bbox не меняется** (остаётся 1500)

**Причина:** в qsketchmetric длина параметризуется (`c:W-2*FW`), а **положение** (`x=W/3`) — константа. При `W:900` вертикальный импост остаётся на `x=500` (от 1500), должен `300` → разъезжается.

**DXF:** `real_output/qsketchmetric_tutorial_*.dxf 16K`, `qsketchmetric_OK1_ABSTRACT_60_80.dxf 18K` (все 4 варианта одинаковые)

**Вывод:** годен для простых деталей (стойка, ригель), но не для окна `3×2` — нет `LWPOLYLINE`, нет `continuous`, нет `bead/sash/filling/blocks`.

## 3. `IfcOpenShell/ifcopenshell` 0.8.1 — реальный `add_window_representation`

**Клон и установка:**
```bash
git clone --depth 1 https://github.com/IfcOpenShell/IfcOpenShell.git repos/IfcOpenShell
pip install ifcopenshell==0.8.1  # 80MB wheel
python real_ifc_ok1.py
python real_ifc_ok1_fixed.py
```

**Реальный прогон (исправленный API):**
```python
model = ifcopenshell.file(schema="IFC4")
proj = api.root.create_entity(model, IfcClass="IfcProject", name="WinPlax OK-1")
ctx = api.context.add_context(model, context_type="Model")
body = api.context.add_context(model, context_type="Model", context_identifier="Body", target_view="MODEL_VIEW", parent=ctx)
rep = api.geometry.add_window_representation(
  model, context=body,
  overall_width=1.44, overall_height=1.44,  # метры
  partition_type="SINGLE_PANEL",
  lining_properties={"LiningDepth":0.07, "LiningThickness":0.06, "MullionThickness":0.08, "TransomThickness":0.08}
)
# rep = #50=IfcShapeRepresentation(Body,SolidModel,(#18,#29,#40,#49)) — 4 extruded solids (frame, lining, bead, panel)
model.write("real_output/ifc_OK1_SINGLE.ifc")  # 50 entities, 1.4×1.4 м
```

**Успешно:** `SINGLE_PANEL` — 4 solids (outer 1.44, inner 1.415, etc.), IFC `50` строк.

**Неуспешно:** `DOUBLE_PANEL_VERTICAL / TRIPLE_*` → `list index out of range` — для `3×2` IFC нет пресета, нужен `SINGLE + ручные IfcMember` (как WinPlax). `3×2` (6 панелей) из коробки не собрать.

**DXF/IFC:** `real_output/ifc_OK1_SINGLE.ifc 3K` (реальный IFC4), `ifc_OK1_1440x1440.ifc 9` (заглушка)

**Вывод:** формула `cell_w=(Overall-2*frame-(cols-1)*mullion)/cols =386.6` совпадает, `LShape` 45° — эталон, но нет `bead outer larger`, `falz 5`, `continuous auto`.

## 4. `FreeCAD-WindowFrames` (jsinger0420) — реальный `geometry.build` (чистый Python)

**Клон и запуск:**
```bash

python real_freecad_windowframes_ok1.py

```

**Реальный прогон (без FreeCAD):**
```python
p=WindowParams(opening_width=1500, opening_height=1500, rows=2, columns=3,
               clearance=30, frame_width=60, frame_depth=70, muntin_width=80)
boxes,pw,ph = build(p)  # 15 boxes: 4 frame +5 muntin +6 glass, pw=386.67 ph=620.0
```

| Вариант | `pw × ph` (glass) | boxes | `dag` |
|---|---|---|---|
| `ABSTRACT 60/80 3×2 Fixed` | `386.67×620.00` | `15` | `405/430` |
| `S571 58/77 3×2 Fixed` | `390.00×623.50` | `15` | — |
| `REHAU 63/76 3×2 Fixed` | `387.33×619.00` | `15` | — |
| `DoubleHung 2×3` | `603×234` | `36` (8 sash +2 bead +10 muntin +12 glass) | — |

**Сравнение с WinPlax:**
- `pw 386.67` совпадает с `cell_w 386.67` WinPlax (формула идентична)
- Но `glass 386×620` vs WinPlax `FIX 376×595` (на `10` меньше — `falz 5×2`) и `sash 272×491` (на `114` меньше — профиль створки `80` + `overlap 28`)
- `WindowFrames Fixed` — все глухие, нет `per-cell sash_type TURN/TILT`, нет `bead outer larger`, нет `sill 30` (ph 620 vs 605)

**DXF:** `real_output/windowframes_OK1_ABSTRACT_60_80_3x2_Fixed.dxf 21K` (прямоугольники frame/muntin/glass, Front view `X=width Z=height`), `S571`, `REHAU`, `1×1 900`, `DoubleHung` — всего 5 DXF, все валидны (`ezdxf` 30 ents)

**Тесты:** `python -m unittest discover -s tests -v` → `15 tests OK`

**Вывод:** `geometry.py` — лучший валидатор сетки WinPlax, `scaling.py` / `stl_writer.py` дают `STL` `1:22.5…1:220` для макета, но не замена.

## 5. `OpenAEC/open-pdf-studio` frame element — реальный `js/gevelelement/indeling.js` (Node)

**Клон и запуск:**
```bash
git clone --depth 1 https://github.com/OpenAEC-Foundation/open-pdf-studio.git repos/open-pdf-studio
node real_open_pdf_studio_ok1.mjs  # ES module, indeling() + weergave()
```

**Реальный прогон (Node, реальные модули):**
```js
import { indeling } from './js/gevelelement/indeling.js';
import { preset } from './js/gevelelement/catalogus.js';
// vliesgevel 50×150, kozijn 67×114, presets PRESET_IDS
let p = {lengte:1440, stijlen:[{pos:480},{pos:960}], kader:['alu-50x150','alu-50x150'], panelen:['glas','glas','glas']};
indeling(p,'vliesgevel') // → lengte 1440, 4 stijlen, 3 velden, dag 405/430/405
```

| Пресет | `lengte 1440` 3 поля | `dagMm` (свет) | `diepte` |
|---|---|---|---|
| `vliesgevel 50×150` | `stijlen 25,480,960,1415` | `405 / 430 / 405` | `150` |
| `kozijn 67×114` | `33.5,480,960,1406.5` | `379.5 / 413 / 379.5` | `114` |
| `winplax-60/80 кастом` | `30,486.66,953.33,1410` | `386.66 ×3` | `70` |

**Кастом `winplax-80x70`:** `registreerStijlType({id:'winplax-80x70', breedteMm:80, diepteMm:70})` → `dag 386.66` **точно совпало** с WinPlax `cell_w 386.66`.

**Ограничение 1D vs 2D:**
- `indeling` — `1D` вдоль длины (только вертикальные импосты), для `3×2` нужен второй `indeling` по высоте (`720` на 2 поля) — два вызова, а WinPlax — один `cols×rows 3×2` (2 vertical цельные + 3 horizontal порезанные)
- Нет одновременного `vertical+horizontal` — `2D` только как два `1D` элемента, WinPlax `continuous auto` `vertical`.

**Панели:** `glas / dicht / deur / draairaam` — `draairaam` как `TURN` есть, но нет `TURN_TILT/TILT` per-cell.

**JSON:** `real_output/open_pdf_studio_OK1_indeling.json 5.3K` (3 индента)

**Вывод:** `catalogus + indeling + weergave` (filled rect mullion, double line glass, hatch, door swing) — лучший донор UI, `weergave.tekenOpdrachten` даёт команды `polyline/line/arc` для DXF.
